## 1. 基础显示测试 (Emoji 与字体)

在一些老设备中，因为老旧操作系统的系统字体库缺少 Unicode 新版本的 Emoji 定义，导致相关 Emoji 表情无法正确显示，尤其 Android 版本 11（API 级别 30）及更低版本无法更新表情符号字体，因此若要在这些版本上显示最新的表情符号字体，用户层面必须手动进行更新设备。

**该问题我已经尝试在服务端/代码层面强制绕过系统字库来解决，但是缺少足够的测试样板。**

请查看下表，确认你能正常看到的最高等级。

| 测试等级 | Emoji 样例 | Unicode 版本 |
| :---- | :---- | :---- |
| **基础 (Level 1\)** | 😂 (笑哭)、🚀 (火箭) | Unicode 6.0 (2010年10月) |
| **进阶 (Level 2\)** | 🫠 (融化)、🥹 (忍泪) | Unicode 14.0 (2021年9月) |
| **最新 (Level 3\)** | 🐦‍🔥 (凤凰)、🍋‍🟩 (青柠) | Unicode 15.1 (2023年9月) |
| **前沿 (Level 4\)** | 🫪 (憨憨/大聪明)、🧑🏻‍🐰‍🧑🏼 (兔耳人) | Unicode 17 (2025年9月) |

| 测试等级 | 说明 |
| :---- | :---- |
| **基准线 (Level 1\)** |所有智能设备均应正常显示。 |
| **主流线 (Level 2\)** |不是太老设备应该都可见。 |
| **测试线 (Level 3\)** |iOS 17.4+ / Android 15+ / Windows 11 24年6月累积更新+ / macOS Sonoma 版本14+ 可见。 |
| **压力测试 (Level 4\)** |预计将于 2025 年底和 2026 年全年陆续上线各大平台，目前几乎无硬件厂和APP没来得及跟进适配，看不到很正常。 |

注：各个平台（包括各硬件大厂和各APP大厂）都有各自独有的emoji转译表情库，并且 Unicode 为其许多表情符号定义了变体序列，以指示它们所需的显示方式，所以不同设备、不同浏览器看到的表情未必一致，但只要能显示出来就没问题。

- [ ] Emoji 显示问题
  * **异常现象**：显示为 □□ (方块/豆腐块) 、 ? 或者多个符号拆分显示（如凤凰显示为“鸟+火”）。  
  * **如果你在 Level 1 或 Level 2 看到的是方块，请截图告诉我你的设备型号。**。

## 2. PC 端 (电脑访问)

如果你正在使用电脑浏览，请帮忙关注：

- [ ] **排版渲染**  
  * 悬浮预览卡片是否正常？例如：[[网页实际渲染-预览页]]，**鼠标悬停可直接悬浮卡片形式显示完整文章内容。**
  * 请访问上面这个测试页，点击链接可跳转，检查大标题、列表、引用块（带有颜色的框）是否显示正常，有没有文字重叠或超出屏幕。  

- [ ] **功能交互**  
  * **搜索框**：按下 Ctrl + K (或点击搜索图标)，输入“测试”，能否弹出搜索结果？

## 3. 移动端 (手机/平板访问)

**这是测试的重点**，Quartz 框架在小屏幕上更容易出现布局问题。

- [ ] **布局与遮挡**  
  * **图谱视图**：文章底部的“关系图谱” (Graph View) 是否会遮挡正文内容？  
  * **表格显示**：如果文章中有表格（比如：[[笔记杂项页]]），是否可以左右滑动？还是被强行挤压变形了？
  
- [ ] **阅读体验**  
  * 字体大小在你的手机上是否合适？

- [x] 移动端 下滑刷新（全面屏操作逻辑）可能失效。
  * 具体问题：连续点击多个站内链接（比如两个全局都存在的链接互相交替点击）从而不停跳转，最终停下时一定会导致浏览器的“下滑刷新”（全面屏操作逻辑）失效，只能使用浏览器的手动刷新按钮，但是反复点击单一链接时则不会出现这个问题...
  
  * **已解决，若能进一步复现，请告诉我**。
